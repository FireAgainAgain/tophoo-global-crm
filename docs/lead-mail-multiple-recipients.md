# 同一线索的多联系人开发信

从线索列表打开开发信，点击「发送邮件」后，可在发送确认窗口勾选该公司的多位联系人，也可全选或补充一个其他收件邮箱。收件人在发送时选择，草稿编辑窗口只编写邮件内容；同一邮箱忽略大小写去重，未填写有效邮箱的联系人不能勾选。

桌面发送窗口左侧选择联系人，右侧预览正文和附件。「添加附件」打开文件选择器，可逐次添加并在提交前移除；每次最多5个文件、合计10 MB。独立加载 `mail-send-review.css`，避免重新生成公共样式包后丢失多选窗口样式。

点击确认后，每位联系人各发送一封独立邮件，同一标题、正文、签名和附件随每封邮件发送。不会自动改写正文中的称呼，因此发送前需要检查是否适用于所有所选联系人。

窗口逐人显示服务器接受、失败、处理中或结果待核实。每封邮件使用独立的发送编号，沿用已有服务端幂等和发送记录机制。发送后不再自动生成联系记录，也不会改变线索状态或已联系标记。

联系人卡片和发送时的联系人列表显示「未发开发信」或「已发开发信 · N 封」。只统计该线索下、当前邮箱对应的服务器已接受邮件；忽略邮箱大小写，失败、待核实和重复请求不累计。点击联系人卡片的标记，可分页查看发送日期、主题、正文和附件名称。已有发送记录自动参与统计；历史联系记录保留，手动转为联系记录仍可使用。

部分发送失败后，「继续发送」只处理明确失败和尚未提交的联系人。结果不确定时暂停当前队列，可查询该次发送记录；不会自动重发不确定或已接受的邮件。查询确认服务器没有该编号记录时，可以由用户主动继续提交原编号，利用服务端幂等避免重复。确定失败的重试使用新的发送编号。

开始提交后收件人、正文签名和附件在本窗口中锁定，以确保查询与重试对应同一封邮件。切换项目或账号会停止后续联系人。当前窗口通过前台逐封提交，关闭页面会中断尚未提交的队列；已提交的邮件可在个人邮箱发送记录中查询。服务器接受只表示发件服务器已接受，不表示收件人已收到或阅读。

新增只读接口：`GET /api/mail/deliveries/by-request/{request_key}`。仅本人可查询，支持查找超过最近50条范围的记录，不触发发送。

验证包含邮箱去重、未填写邮箱、逐人附件、部分失败、网络中断后的查询恢复、原编号安全重试、切换项目停止队列及桌面/手机布局；所有邮件发送验证均使用模拟接口或模拟SMTP，不发送真实开发信。
