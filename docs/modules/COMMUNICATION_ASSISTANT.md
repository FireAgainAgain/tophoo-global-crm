# 全球时间

入口：**CRM → 工具 → 全球时间**。线索与客户详情的公司资料下方，也会显示当地时间信息条。

## 使用方式

| 功能 | 操作 |
| --- | --- |
| 城市时钟 | 卡片展示当地时间、日期、昼夜、时差与工作状态；星标关注，按添加顺序显示 |
| 时间对照 | 选择北京时间或拖动 24 小时时间轴，统一对照各地日期、夏令时与工作状态；点击“回到现在”恢复实时 |
| 当前状态 | 按当地时间、工作日、工作时段及公共假日计算；按分钟刷新，不代表客户在线 |
| 地区安排 | 点击城市打开侧栏（显示当前实际时间），查看下次工作时段、未来 7／30 天假日和共同工作时段 |
| 时间换算 | 输入客户当地时间或北京时间；复制结果，客户详情中可带入现有跟进计划，确认保存后才创建计划 |
| 我的作息 | 设置本人时区及工作时段，用于查找未来两周双方重叠的工作时间 |
| 公司与联系人 | 详情侧栏切换公司或联系人，单独设置沟通地区、作息和实际休假；联系人未设置时继承公司 |

参考作息默认是周一至周五 09:00–12:00、13:00–17:00，并非各国统一营业时间。可设置不同周末、多个时段和跨午夜班次；实际确认后可标注“客户已确认”。公共假日默认按休息处理，客户照常营业时可关闭此选项，假日信息仍会显示。

客户与线索的当地时间优先采用已保存的联系人／公司安排；未设置时，单时区国家自动识别，中国默认使用北京时间。多时区国家会尝试将公司地址与时区目录中的中英文城市名匹配，只有唯一匹配时才自动采用；地址缺失、无法匹配或包含多个候选城市时才提示补选城市，不会默认使用首都。自动识别不写入设置表，修改国家或地址后会重新判断；手动设置始终优先。客户所在城市不在代表城市列表中，可选择适用时区并补充城市名称。地方假日需另选适用行政地区；暂缺数据会明确提示。

时间轴日夜色带按当地 06:00–18:00 示意，不代表实际日出日落或营业时间。时间对照只做临时计算，不保存设置；从对照状态打开城市，会自动带入该北京时间换算。

## 保存范围与权限

- 当地时间、时差、工作状态及换算结果实时计算，不存为线索或客户，不计入客户统计。
- 关注地区、本人作息和地区参考设置按 **用户＋项目** 独立保存；只读成员也能管理自己的参考设置。
- 公司及联系人设置按当前项目关联，查看还要求对应线索／客户模块查看权；保存或重置要求全球时间及对应业务模块均可编辑，并沿用负责人范围。只有全球时间权限时仍可使用地区查询和个人参考设置。
- 线索转客户时迁移沟通设置，已有客户设置优先保留；转换快照保留原线索设置。联系人或项目客户关联被删除时清理相应设置，放入公池时保留。
- 线索详情提供时间参考与复制，不新增线索跟进安排。普通地区查询可查看同一时区的已授权在跟客户，多时区但未明确地点的客户不会被猜测归类。

## 数据与维护

时间采用 IANA 时区规则，由 `tzdata` 提供；公共假日使用 `python-holidays` 本地规则，支持的行政地区因国家而异。无需 API Key、AI 或逐次外部接口请求。假日名称采用英文，便于对外沟通；临时公告、未来调休和企业实际营业情况仍需核对。

夏令时跳时导致不存在的时间会提示重新选择；回拨导致重复的时间需选择第一次或第二次。没有共同工作时段时如实提示，不补造推荐时间。

| 内容 | 位置 |
| --- | --- |
| 个人关注与参考设置 | `crm_communication_preferences` |
| 公司与联系人设置 | `crm_communication_settings` |
| 计算、校验与接口 | `app/services/communication.py`、`app/schemas/communication.py`、`app/routers/communication.py` |
| 页面与样式 | `communication_assistant.html`、`communication-assistant.js`、`communication-assistant.css` |

数据库备份应包含以上两张设置表。新部署安装 `requirements.txt` 后启动会建表；假日规则在进程内缓存，升级 `tzdata`、`holidays` 并同步依赖版本后重启，使用新版规则。测试入口为 `tests/test_communication_assistant.py`、`tests/communication_assistant_ui.cjs`，测试目录由 `pytest.ini` 限定，避免执行临时迁移脚本。
