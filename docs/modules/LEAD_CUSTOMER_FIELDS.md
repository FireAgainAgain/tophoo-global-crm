# 线索与客户字段约定

线索和客户共用同一套新增、编辑分区；仅公司名称必填。字段在转换前后保持相同名称和含义。

| 分区 | 共同字段 | 转换规则 |
| --- | --- | --- |
| 公司资料 | 公司名称、国家 / 地区、企业类型、公司官网、公司地址、公司社交主页 | 新建客户时带入；合并已有客户时只补空值 |
| 联系人信息 | 联系人、邮箱、电话、WhatsApp、个人社交主页、联系人备注、主联系人 | 保留多位联系人；匹配已存在联系人时只补空值 |
| 来源与管理 | 来源方式、归属（有管理权限时） | 转入对应项目关系；保留已有归属冲突检查 |
| 公司备注 | 公司业务、需求摘要、待核实事项 | 对应 notes；与联系人备注分开保存 |

原来线索表单的“备注”和客户表单、客户导出的“其他信息”，统一为“公司备注”。联系人级 notes 对应“联系人备注”；旧版 other_channels 作为主联系人备注兼容保留。历史 customer_source 仍按原值保留，不清空、不与 source_type 混写。

线索开发状态用于转换前的开发过程；客户分级按A–G标记重点客户、询盘阶段及产品匹配情况，二者不互相转换。转换历史保留原线索快照；合并客户时与现有非空字段不同的原资料可在转换历史查询。添加日期、修改日期属于系统记录，不作为用户编辑字段。

新增、编辑和详情均按“公司资料 → 联系人信息 → 来源与管理 → 公司备注”排列。客户分级仅在客户模块显示；归属变更的跟进转交选项仅在管理员编辑客户时显示。公司资料记录企业事实，联系人记录个人联系资料，联系记录保存每次沟通过程，RFQ 保存询价及技术参数。

验证：线索转换及多联系人相关接口检查；表单在桌面和手机宽度下的新建、编辑回填、多联系人提交和备注隔离检查。界面检查使用拦截后的示例接口，不写入真实客户数据。

详情中的四个基础区块使用相同编号与配色，字段按表单顺序展示。来源、归属、客户分级或线索联系状态以及系统日期集中在“来源与管理”；公司备注单独展示。跟进计划、开发内容和联系记录排列在四个基础区块之后。
