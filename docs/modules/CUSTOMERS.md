# 线索列表、客户列表与客户公池

更新日期：2026-10-13。本文描述 TOPHOO Global 当前界面，入口为「客户」，默认服务端口为 8002。

## 当前搜客流程

独立搜客清单入口已移除，搜索结果和原搜客清单资料在「自动获客」统一管理。支持全部企业、按批次查看、手动新增、核实和删除，直接转入线索，不再需要确认入清单。历史清单接口保留兼容。详细说明见 [自动搜客](AUTO_PROSPECTING.md)。

## 列表与详情

列表以浏览资料为主，不再显示归属列和单条操作列。点击公司名称或联系人打开右侧详情，列表的筛选、页码和滚动位置保持不变。

线索详情仅展示公司资料、全球时间和来源信息，不展示联系人、联系记录或开发信；底部左侧为“删除线索”，右侧为“编辑资料”和“转为客户”，不再提供“联系记录”和“更多操作”按钮。联系人、联系记录及开发信从线索列表各自的独立入口查看和维护；已有数据保留。客户详情仍展示联系人和联系记录。

| 列表 | 显示的信息 | 详情中的主要操作 |
| --- | --- | --- |
| 线索列表 | 公司 / 联系人（含官网）、当前状态、资料完整度、人工背调、开发信、国家 / 地区、当前时间 | 编辑资料、转为客户、删除资料 |
| 客户列表 | 上述资料及客户分级 | 编辑资料、沟通概要、导出 MD、导出 PDF、放入公池 |
| 客户公池 | 公司、联系人、官网、国家/地区、联系方式、来源、释放原因、释放日期、停留天数、释放人 | 恢复客户、删除资料 |

邮箱、电话和官网可直接点击使用。未填写的信息显示相应提示或「—」；停留天数按释放时间计算。添加日期固定不随编辑、分级或跟进变化：线索取创建时间，客户取加入当前项目的时间。修改日期保留在详情里，不代表最近联系日期。客户详情另外显示最近三条沟通概要，按联系时间倒序排列。

归属信息仍在管理员详情中显示，管理员也可通过「全部归属」筛选。移除列表归属列不改变项目访问范围和后台权限。

搜客资料的新增、编辑、删除和转为线索统一在自动获客页面完成。

## 搜索、筛选和分页

- 搜索覆盖公司、联系人、客户来源、来源类型、国家、邮箱、电话、WhatsApp、官网、备注、释放原因及接口返回的归属名称。
- 可按国家、客户来源筛选；客户列表额外支持产品匹配度 A–D 和客户分级 A–E 的独立筛选，未评估或未分级也可筛选，管理员可按归属筛选。
- 排序控件分为「排序字段」和「方向按钮」：字段只列添加日期、公司名称及客户列表专属的客户等级；方向按钮显示新到旧/旧到新、A→Z/Z→A 或 A→F/F→A，点击即可反向排列。未分级始终位于等级排序末尾，排序字段和方向均按项目、列表记住。
- 默认按添加日期从新到旧排序；可点击添加日期表头切换顺序，也可按公司名称或客户等级排序。支持添加日期起止范围筛选（包含起止当天）；公池的时间排序与范围筛选使用释放时间。
- 每页可显示 25、50 或 100 条，可输入页码直接跳转。表头固定，记录多时在表格区域滚动；手机端支持横向滚动查看完整列。
- 「清空筛选」清除搜索和筛选条件，并恢复默认排序。
- 当前浏览器会话按项目和列表分别记住筛选、排序、每页条数、页码和滚动位置；页面重新加载后仍保留这些状态，清空筛选恢复默认添加日期排序。
- 记录少时表格按内容自然收缩。已取消 180 像素的最小容器高度，避免只有一条线索时下方出现多余空白。

分页、搜索和筛选目前在前端执行，接口仍读取当前用户有权查看的列表数据；本轮未引入服务端分页。

## 编辑和保存

通过顶部「新增」或详情中的「编辑资料」打开表单。线索只需填写公司名称，其余资料可后续补充；来源类型和默认归属沿用现有规则。客户公池不提供新增入口。

客户表单将公司资料中的「备注」改为「其他信息」，联系人的「其它渠道」改为「备注」，原内容保留。每个客户可保存多位联系人，每位联系人包含联系人、邮箱、电话、WhatsApp 和备注。有联系人时只有一位主联系人，也允许客户暂时没有联系人。

整份客户表单支持新增、编辑、选择主联系人和删除已保存的联系人，点击「保存」后统一生效。删除前会提醒，删除主联系人后暂由第一位剩余联系人接替，可继续调整。尚未保存的新联系人可点击「取消新增」。关闭表单放弃修改时，已暂删的联系人仍保留。

客户列表显示主联系人的姓名及联系方式，并显示联系人数量；搜索也覆盖其他联系人的姓名、邮箱、电话、WhatsApp 和备注。重新打开编辑时可修改所有联系人。旧客户原有的联系人自动保留为主联系人，其他信息与联系人备注分别保存。

编辑支持 Ctrl/⌘+S 保存。存在未保存输入时，关闭表单或通过界面导航切换前会提醒；取消放弃操作可继续编辑。保存期间禁用重复提交和界面上的上下文切换。保存失败时保留输入，便于重试。

关闭表单使用取消按钮、关闭按钮、背景遮罩或 Esc。成功新增后回到第一页并清空筛选，便于查看新记录。

## 批量处理

勾选仅作用于本页。「全选」选择本页所有记录，部分选中时显示半选状态。筛选、翻页或切换列表会清除勾选，避免隐藏记录被带入批量操作；也可点击「取消选择」。

| 操作 | 使用方式 |
| --- | --- |
| 线索转为客户 | 勾选后一次确认 |
| 客户放入公池 | 勾选后统一填写释放原因，一次确认 |
| 公池恢复客户 | 勾选后一次确认；管理员可指定统一归属或保留各自原负责人，普通成员恢复后归属自己 |
| 删除 | 线索、公池和搜客清单可批量删除，执行前确认；客户列表不提供删除入口 |

放入公池和恢复客户沿用现有单条接口逐项执行，可能部分成功。失败时显示已经完成与剩余未完成的数量，刷新列表，并保留仍在本页的未完成记录供重试；不会自动回滚已经成功的记录。

公池删除受后台 RFQ 关联检查约束。删除当前项目的客户关联及相应沟通概要，不会删除共享的工作区客户主档；线索删除则删除对应的线索记录。

## 沟通概要与档案

客户详情按公司资料、联系人、跟进计划、沟通概要分区。公司区不重复展示主联系人资料；未填写的可选字段不占行，社交主页以平台链接展示。修改日期等档案信息以次要文字显示。

客户详情显示最近沟通概要，点击「沟通概要」查看或维护。返回后重新打开该客户详情，保留列表位置。底部直接提供「编辑资料」「沟通概要」，Markdown / PDF 导出与「放入公池」收进「更多操作」，不再进入独立完整档案页面。

在详情中点击「编辑资料」，保存成功后刷新详情和列表，再次编辑使用最新资料。导出文件包含公司资料、全部联系人及沟通概要，按公司名称命名；导出失败提示原因并允许重试，不关闭详情。

详情展示全部联系人并标明主联系人；Markdown 和 PDF 导出包含每位联系人的完整信息。

详情侧栏提供「新增联系人」，每张联系人卡片直接提供「编辑」「删除」「设为主联系人」。新增或编辑使用独立的五字段表单，只保存这一人的资料，不提交整份客户数据；设为主联系人立即生效，列表与详情同步更新。

删除联系人需要确认。删除主联系人且仍有其他联系人时，确认框需选择接替人；删除最后一位后显示「暂无联系人」，保留客户、RFQ 关联和历史沟通概要。删除后不会在服务重启或原有数据迁移时重新生成联系人，后续新增的首位联系人自动成为主联系人。公池中的客户需先恢复，才能管理联系人。

列表、详情和沟通概要会校验项目及请求版本，忽略快速切换后的旧响应。权限范围和数据模型沿用现有后台接口，不因本轮界面调整而扩张。

## 多联系人在搜客流程中的流转（2026-10-10）

搜客资料、线索和自动获客结果均支持每家企业最多 100 位联系人，字段与客户列表一致：姓名、邮箱、电话、WhatsApp、备注，并选择一位主联系人。列表展示主联系人和联系人数量，详情展示全部联系人。自动搜客结果及线索通过编辑资料统一维护联系人；公池可查看全部联系人，恢复客户后再编辑。

自动获客核实弹框可新增、编辑、移除联系人。官网公开邮箱和 Hunter 返回的多个邮箱会保留为多个联系人；公开邮箱不代表已验证，也不会据此虚构联系人姓名。搜索结果直接转为线索、再转为客户时完整传递联系人。搜索覆盖次要联系人的资料。

线索转客户结合官网域名和全部联系人邮箱匹配同一工作区客户。匹配成功时追加新联系人，已有联系人的非空资料及原主联系人保持不变；公司资料仅补充空字段，负责人不自动覆盖。出现多个匹配客户、同名但无可靠身份信息、已有其他负责人或企业仍在公池时，转换返回明确提示，线索保留，需核实资料、协调归属或恢复客户后再转换。

升级仅增加可空的 contacts_json 字段，旧搜客资料、线索和结果仍可读取为单联系人；新的多联系人数据单独保存，同时同步主联系人摘要供旧接口使用。转换后搜索历史保留，解除其对已转换搜客清单行的引用。


### 公司与联系人的社交主页（2026-10-10）

公司资料及每位联系人分别支持 LinkedIn、Facebook、Instagram、YouTube 主页链接。搜客清单、线索、客户、公池及自动获客结果均展示并在流转时保留；公池通过详情查看，恢复客户后维护。链接位于编辑表单和详情中，不增加列表列数。客户详情的 Markdown/PDF 导出包含这些链接。清空输入并保存可删除链接；旧接口未提供相关字段时保留原值。

## 企业类型

企业类型表示企业业务角色，与线索、客户、公池等管理状态无关。自动获客、线索、客户和公池共用 `company_type`：支持经销商、进口商、批发商、零售商、制造商、工程承包商、供应商、终端用户、服务商，也支持自定义；选填，留空表示未知。

转为线索和客户时保留类型，合并已有客户时只补充空值，不覆盖已有类型。客户详情、编辑和档案导出显示企业类型；客户列表、线索和公池支持企业类型筛选及搜索，列表不增加独立列。中英文常见类型统一保存，纯数字值不合法。旧客户端未提交该字段时保留已有值；历史搜客结果与线索仍有明确关联时补回缺失类型。自动识别的类型需人工核实，不代表已确认采购意向。

## 2026-10-11 线索转客户修复

单条和批量操作均通过批量转换接口提交选中编号。单条转换路由使用整数路径匹配，避免将 `batch` 错当成线索编号而返回 422。同步修正旧搜客清单转线索路由。转换保留多联系人和企业类型，保留同名、多人匹配、不同负责人和公池等冲突校验；只读成员不得转换。

前端请求统一声明 JSON 类型，并更新资源版本以刷新旧缓存。覆盖实际批量接口、详情单条按钮、多联系人、企业类型、只读权限及客户浏览的回归验证。排查仅做事务回滚检查，不替用户转换现有线索。

线索和客户列表默认按添加日期从新到旧排序，同一时间用记录 ID 保持确定顺序。客户列表仍可手动选择等级 A、B、C、D、E、未分级排序，同等级按添加日期从新到旧排列；清空筛选恢复添加日期排序，保存资料保留当前筛选、排序和页码。公池继续按释放时间排序。


## 跟进计划管理（2026-10-13）

第一版用于客户列表。点击列表“下次跟进”列直接打开该客户的跟进管理窗口，不展开客户详情；窗口可查看待完成、逾期及历史计划，支持新增、修改、完成、取消和删除。点击公司名称仍可进入详情管理全部计划。客户可有多个计划，列表仅展示最近一条待完成计划的时间和事项。

- 必填事项和日期时间，可选现有联系人、补充说明；负责人默认本人，管理员可选择拥有该客户访问和编辑权限的人员。
- “我的跟进”默认查看本人待完成计划，支持今天、逾期、未来、已完成及已取消筛选和分页。管理员可切换当前项目全部计划。客户详情可打开该客户的计划历史。
- 待完成、已完成、已取消为保存状态；逾期按时间自动判断。今天包括今天到期的全部待完成计划，与逾期可能有交集；日期分组按北京时间。
- 改期或编辑不新增沟通概要。完成时必填实际联系时间、沟通渠道及结果，保存后写入沟通概要；可同时安排下一次计划，任一内容校验失败均不提交。重复完成不会重复生成记录。
- 取消可填写原因，保留计划历史。释放公池时提示并取消该客户在当前项目的待完成计划；恢复不重新启用旧计划。
- 管理员更改客户归属时默认转交未完成计划，可取消表单勾选以取消原计划；完成及取消历史不变。负责人账号删除时取消其待完成计划，保留历史。移除项目客户或删除项目时清理对应计划，不影响其他项目。
- 保存失败保留草稿，关闭有未保存提醒，项目切换关闭旧上下文。第一版没有邮件、短信或系统推送提醒，待办通过页面查看。

计划数据使用 `crm_follow_up_plans`，项目、客户、负责人和具体联系人关联。新计划时间按 UTC 保存、带时区返回，前端以设备本地时间显示；写入既有沟通概要时转换为北京时间以兼容原记录。

验证：`python -m pytest tests/test_follow_up.py -q`；`node tests/follow_up_ui.cjs`。浏览器测试使用隔离资料和模拟写入，不新增真实客户或计划。

跟进计划以紧凑时间列表显示，左侧日期、右侧事项和联系人／负责人，逾期用橙色与文字标识；直接点击“完成跟进”，编辑／改期和取消收在“⋯”菜单。历史入口和新增按钮位于区域标题旁，空状态说明下一步操作。

## 线索状态与沟通概要

线索当前状态：未查看、背调中、开发中、重点开发中、成功对接、公司对接过、暂不匹配。支持列表修改和筛选。发送开发信、保存我方联系或客户回复均不修改状态，由用户手动选择。

线索“跟进安排”已移除，优先级、应用标签、下次跟进日期及对应历史快照字段经备份后清理。客户阶段的跟进计划保留；转客户不再从线索自动生成计划。

线索和客户共用沟通概要页面，录入仅包含联系人、沟通日期、方式、标题、内容五项。标题用于快速浏览，内容记录需求、结论和下一步；联系人可选择现有姓名或手动填写。历史正文和翻译保留，翻译折叠查看；原方向保留在历史数据中，不再作为录入项。编辑未改变日期时保留原有具体时间。读取失败或保存失败可重试，未保存内容有离开提示。

转客户支持新建与合并，保留公司、多联系人、原文、翻译、联系时间、记录人及记录时间。已有客户的非空资料和主联系人保留；同名但缺少一致身份信息、归属冲突、公池冲突及多客户匹配会提示核实。批量预览检查批次内部冲突；正式转换在同一事务中完成，失败整体回滚。

原线索资料和沟通概要保存到转换历史，线索当前状态不成为客户字段。完整验证见 `tests/test_lead_shared_records.py`。

线索和客户的沟通概要均校验项目读写权限：只读成员可浏览，不能新增、修改或删除。

## 客户沟通参考

线索和客户详情的公司资料下方显示当地时间、作息状态及时差，点击可查看假日并换算时间。未明确城市的多时区国家会要求选择；联系人可继承公司安排或单独设置。客户可将换算时间带入现有跟进计划，线索仅作参考。此类设置和实时结果不影响客户数量或统计；详见 [全球时间](COMMUNICATION_ASSISTANT.md)。

客户列表顶部提供全部客户、A–G 分级及未分级的紧凑统计，点击可筛选。数量按当前搜索、国家、归属、来源等条件及本人可见范围计算，覆盖全部分页；分级筛选不改变概览基数，便于切换比较。

客户列表顶部采用搜索操作＋分级统计/排序两层工具栏，详细筛选默认折叠。点击「筛选」展开；收起后条件继续生效，按钮显示生效条件数量，可用「重置」清空。

线索列表沿用同一紧凑工具栏：状态统计包含全部、未查看、背调中、开发中、重点开发中、成功对接、公司对接过、暂不匹配，点击即可筛选；概览统计忽略状态筛选，保留搜索、国家、来源、资料完整度及可见范围等条件，覆盖全部分页。线索与客户的筛选展开状态分别保留，公池布局不变。

### 开发信草稿

线索详情仅展示标题、正文预览和更新时间；点击“编写开发信 / 编辑开发信”打开宽屏编写窗口，可放大。标题与正文独立填写，中文翻译按需展开，宽屏时并排对照。支持保存草稿、复制标题与正文、未保存关闭提醒。保存草稿不会自动发送或生成沟通概要。系统内发送：先在“系统 → 邮箱配置”保存个人邮箱，再在开发信中点击“发送邮件”，核对发件人、收件人、正文和附件后确认；邮件服务器接受后自动生成沟通概要并更新适用的线索状态。通过 Foxmail 等外部工具发送后，仍可点击“已发送，记录沟通”手动补录；系统已自动记录的邮件无需重复补录。线索转客户时保留原草稿。

开发信窗口关闭时会清理未保存提示、放大、翻译展开和滚动等临时状态；未保存修改需确认放弃，已保存草稿保留。编辑器关闭后不再触发离开页面提醒，切换项目或退出账号会移除原编辑窗口。

### 客户资料导出

客户详情的“更多操作”可导出 PDF 或 Markdown。基本信息集中展示，空字段自动省略，联系人与公共联系方式分开列出；公司备注、沟通概要及历史翻译完整保留。PDF 使用紧凑联系人表、连续排版和页码，长内容自动分页。

旧混合分级已拆分：产品匹配度为 A 对口、B 小对口、C 配件、D 不对口；分级为 A 订单客户、B 样单客户、C 重潜客户、D 普潜客户、E 无潜客户。迁移规则见本文末尾。

客户列表分级列支持直接选择A–G或未分级并自动保存；仅修改等级，保留其他客户资料。保存失败恢复原值，成功后同步筛选、排序和概览计数；接口按项目归属及写权限校验。

客户列表支持按跟进计划筛选：全部、已有跟进计划、未安排跟进计划。以待完成计划为准，逾期仍计为已有计划，只有已完成或已取消历史的客户计为未安排。支持与其他条件组合、筛选数量提示、清空和列表记忆；保存或取消计划后随列表刷新重新计算。


线索国家名称采用简体中文规范值，新增、编辑及导入通过模型保存时转换已知中英文名称、旧称及国家代码；无法可靠识别的地区保留原文。国家筛选改为可输入搜索，支持中文、英文别名和部分名称，候选来自当前列表；可清空和记忆条件。国家清理不修改人工背调、联系状态或其他业务字段。

## 产品匹配度与客户分级（2026-11-02）

客户列表分为两个独立字段，均可在列表直接选择、自动保存，并可点击对应表头切换正反排序；空值始终在末尾，排序会返回第一页。

- 产品匹配度：A · 对口、B · 小对口、C · 配件、D · 不对口；未评估可留空。
- 分级：A · 订单客户、B · 样单客户、C · 重潜客户、D · 普潜客户、E · 无潜客户；未分级可留空。

筛选、添加/编辑、客户详情及客户档案导出同步展示两项，修改一项不会覆盖另一项。统计页面的客户分级使用新的五级含义。

旧混合字段的 C 产品对口 → 匹配度 A；E 产品小对口 → B；D 产品配件 → C；F 产品不对口 → D。旧 A 重点客户、B 询盘阶段、G 虚假客户不足以直接判断订单、样单或潜力，因此不自动赋予新分级。旧字段值备份保存，并保留在客户的 legacy_grade 中。迁移使用 classification_version 标记，只执行一次，不会在重启后覆盖已选择的匹配度或新分级。

数据库新增 product_match、legacy_grade、classification_version，由启动迁移维护；迁移前备份位于 backups/customer-classification-before-split-*.json。


## 按日安排跟进（2026-11-02）

客户列表“跟进”中新增或编辑事项时，可选择跟进日期，默认今天；日期精确到日，不需要填写时分。未保存时修改日期也会触发离开提醒，保存失败保留内容和日期。

按北京时间区分：未来日期为蓝色“未到期”，今天为橙色“今日跟进”，今天之前为红色“已逾期”。客户列表按当前用户最早一条待完成跟进显示颜色和日期；打开跟进后，每条事项单独显示状态和日期。颜色配有文字，完成及删除操作继续保留。

接口新增 due_date（YYYY-MM-DD），内部复用原 UTC 时间字段保存所选日期的北京时间零点；旧 due_at 接口继续兼容。历史记录按北京时间提取日期展示，不批量改写原记录。客户列表、跟进队列和统计的逾期口径一致：今天不算逾期。联系记录中的实际沟通时间继续保留原有精度。


### 线索添加时间排序
