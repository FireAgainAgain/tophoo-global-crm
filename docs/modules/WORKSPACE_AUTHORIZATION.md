# 工作授权与项目角色

系统使用两层权限，最终可用功能取两者的交集。

## 第一层：工作区授权

后台「工作区授权」决定整个工作区可以使用哪些功能。授权目录包含项目、SEO 的建站分组、CRM 的工具和客户分组，以及系统。建站分组包含关键词库和产品记录；询价单、报价单在 CRM 的客户分组中单独授权。所有模块均可取消，项目管理不再强制包含。

## 第二层：项目角色

项目顶级管理员为成员分配自定义角色。角色可分别授权当前模块目录中的 CRM／SEO 业务功能，并配置读写权限；工具分组包含全球时间、沟通话术；客户分组包含自动获客、线索列表、客户列表与客户公池，按各模块授权。每个共享模块支持三种状态：

| 权限 | 可用操作 |
| --- | --- |
| 无权限 | 隐藏入口，接口拒绝访问 |
| 只读 | 查看、搜索、复制和导出；不允许新增、修改、删除、导入或启动写入任务 |
| 可编辑 | 在本人数据范围内查看和维护模块数据 |

保存角色后，读写权限同步到已分配该角色的成员。全球时间、沟通话术在「CRM · 工具」中分别配置权限；授予编辑权不会扩大普通成员的数据归属范围。

顶级管理员拥有工作区授权范围内的全部项目功能，但不能越过工作区授权使用未购买或未启用的模块。

## 旧授权兼容

系统启动时自动迁移旧键：

- `product_research` 转换为知识库和竞品调研。
- `customer_management` 转换为统一客户权限 `contacts`。
- 已移除的产品列表、制造能力、选型、商机、样品订单和销售订单权限会被清理；报价单 `quotations` 仍为有效模块。

套餐管理、项目角色界面、导航显隐和接口校验共用同一模块目录，后续调整导航时应先修改 `app/core/modules.py`。

所有侧栏模块均进入角色权限目录，可设置无权限、只读或可编辑，界面显隐与后端接口同时校验。项目管理、网址导航位于“项目”目录；AI 配置、邮箱配置位于“系统”目录。

| 模块 | 只读 | 可编辑 |
| --- | --- | --- |
| 项目管理 | 查看基本资料、导出项目信息 | 修改项目名称与网站地址；成员、角色、删除和排序仍需相应管理员身份 |
| 网址导航 | 查看、搜索和导出本人在当前项目的网址 | 新增、修改、删除、分类及排序本人在当前项目的网址 |
| AI 配置 | 查看本人的连接摘要与绑定 | 维护、测试及删除本人连接，修改本人绑定 |
| 邮箱配置 | 查看本人配置摘要与发送记录 | 修改本人配置、测试连接及发送邮件；开发信还需线索编辑权限 |

关闭项目管理不会取消项目的选择和切换能力，也不会影响其他已授权业务模块。系统／工作区管理员以及项目顶级管理员仍按现有管理员规则取得权限，且受工作区模块范围限制；普通成员由其项目角色决定。

个人网址和邮箱配置的记录始终按用户隔离，权限只决定能否使用功能，不会分发或共享数据。请求带当前项目的 `X-Project-ID` 时严格按该项目校验；未带项目上下文的个人接口仅在至少一个可访问项目有相应权限时允许。没有工作区成员关系的独立账号保留个人网址和邮箱工具；工作区管理员在尚未建立项目时可使用工作区已授权的个人工具。

个人数据源连接可独立保存、显示和测试，即使客户模块只读也可管理自己的 Key；自动搜索和业务结果修改仍需要客户模块编辑权。旧角色原有读写行为保持兼容，旧查看角色不会自动获得编辑权。

全球时间的地区查询、换算以及个人关注／参考作息仅要求查看权限；保存公司或联系人的独立安排仍需客户模块编辑权限。所有客户相关设置沿用现有负责人可见范围。

全球时间关联资料还需相应业务模块权限：查看线索公司／联系人要求 `leads` 查看权，查看客户或同一时区客户列表要求 `customer_list` 查看权。保存或重置独立安排要求全球时间与对应业务模块均可编辑。

WP 产品／文章 XML 转换是独立文件工具，不写入项目业务数据；要求在至少一个可访问项目拥有对应 TDK 模块查看权。仅有工作区套餐授权、但未加入项目或未分配该模块时，不可调用转换接口。

权限 JSON 应为模块名称数组。异常结构不会按对象键名授予权限；数组中的非字符串项忽略，未知模块名不生效。旧版 `NULL` 写权限沿用旧编辑权限，明确的 `[]` 为只读。
