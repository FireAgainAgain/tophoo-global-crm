# 自动搜客

更新：2026-10-10。入口为 客户 → 自动获客，服务端口 8002。

## 当前流程

**自动搜索或手动新增 → 在自动搜客内核实、管理 → 直接转为线索 → 转为客户。**

独立的「搜客清单」导航已经移除，不再需要确认入清单。原搜客清单资料合并到自动搜客结果，保留归属、联系人、社交主页、公司地址和来源。旧导航状态自动跳转自动获客。历史接口作为兼容接口保留，不作为当前界面流程。

## 搜索与数据源

填写产品关键词即可搜索，国家、客户类型、行业和排除关键词可选。搜索自动加入企业相关搜索意图，明确的百科、学校、研究文档页面不作为企业候选。关键词匹配兼容复数、连字符和常见词序，避免把 Heat Exchangers 错判为不匹配 Heat Exchanger。网页管理名（如 admin）不会作为公司名。相关网页不代表有采购意向；未核实的名称显示网站域名与原搜索标题，仍需人工判断企业身份、客户类型和需求。

平台支持 Tavily、Exa、Firecrawl、Serper、Brave，Hunter 可选用于补充邮箱。每位用户在当前项目使用自己的 Key 和额度，连接、测试、密钥显示均在数据源指南中管理。指南提供官网、Key 获取和费用页面；测试时间和结果绑定当前密钥。搜索上限 1–20 条；邮箱补全按缺少邮箱且已核实的企业限额调用，不保证找到邮箱。官网读取不调用 AI，也不消耗搜索平台额度。搜索测试及执行会使用平台额度。

## 企业结果管理

- 「全部企业」汇总历史搜索、手动新增和导入资料；点击批次可查看单次结果和任务进度。
- 默认「待处理」显示待跟进、待核实的企业；「全部记录」可查看筛除、重复、忽略和已转线索的数据。
- 支持新增企业、编辑公司与多位联系人、选择主联系人、批量转为线索、忽略和删除。
- 待核实资料需先编辑保存后再转为线索；已转线索的结果保留历史快照，在线索列表维护业务资料。
- 公司及每位联系人分别保存 LinkedIn、Facebook、Instagram、YouTube 主页；搜索覆盖联系人和社交链接。
- 原搜客清单的编辑资料优先保留；多个历史批次的同一企业保留一条可跟进主记录，重复来源保留在对应批次，并补充不重复的联系人邮箱。
- 已有名单可按界面列顺序整理导入。手动新增企业无需平台 Key。

## 统计与删除

「原始记录」是搜索返回或手动/导入新增的数量；「已保存结果」是当前保留的明细行；「待跟进 / 待核实」和「已转线索」按实际状态计算。这些统计不是同一口径：同批次去重、删除和未完成任务都可能使原始数量大于明细数量。

批次进度显示实际整理数，不把尚未处理的网页当成重复数据。效果复盘放在进度下方、数据上方。历史任务中明确的非企业页面重新标为筛除；错误的数字客户类型保留在来源证据中，展示为待核实。旧页面正文保留作证据，企业简介展示摘要，减少导航文字混入资料的问题。

删除某条结果或整个搜索批次只删除搜索资料；已经生成的线索、客户及其联系人不会被删除。全部企业视图支持跨批次删除，检查用户权限及相关任务状态。正在执行的批次需先停止，再编辑或删除。任务失败保留已完成结果，不会伪装成正常完成。

## 验证

后端回归包括直接转线索、多联系人及社交链接传递、旧清单合并、归属与项目隔离、跨批次删除、删除历史后保留线索、非企业页面分类和统计口径。浏览器验证连接管理、执行与停止、核实、直接转线索、全部企业、手动新增、删除、批次切换、移动端和旧导航兼容，使用模拟数据，不发起付费请求。

## 企业类型

企业类型表示企业业务角色，与线索、客户、公池等管理状态无关。自动获客、线索、客户和公池共用 `company_type`：支持经销商、进口商、批发商、零售商、制造商、工程承包商、供应商、终端用户、服务商，也支持自定义；选填，留空表示未知。

转为线索和客户时保留类型，合并已有客户时只补充空值，不覆盖已有类型。客户详情、编辑和档案导出显示企业类型；客户列表、线索和公池支持企业类型筛选及搜索，列表不增加独立列。中英文常见类型统一保存，纯数字值不合法。旧客户端未提交该字段时保留已有值；历史搜客结果与线索仍有明确关联时补回缺失类型。自动识别的类型需人工核实，不代表已确认采购意向。
