# 线索官网联系人查找

在线索详情的「联系人信息」旁点击「查找联系人」，使用公司官网或具体公开页面开始扫描。扫描在后台运行，关闭窗口后可再次打开查看最近一次结果。

结果默认不选中。核对姓名、职位、联系方式及公开来源后，勾选结果，再选择要补全的已有联系人或自动去重 / 新建。保存只补全联系人姓名、邮箱、电话和 WhatsApp，不将来源、原文、职位说明或采集日期写入联系人备注；已有备注原样保留。不改变线索状态、已联系标记、人工背调标记、公司备注，也不会发送邮件。

可按有邮箱、有电话、有 WhatsApp、已存在、待核对归属、未匹配筛选，并结合关键词搜索。相同邮箱（忽略大小写）或相同的规范化号码标记为已存在，展示对应联系人及匹配依据；仅同名提示可能已存在，需核对归属。保存后重新计算匹配情况。

每行支持删除结果，也可确认后清空本次扫描结果。删除持久化到该扫描任务，刷新和重新打开不会恢复；只影响查找结果，不会删除现有联系人。重新扫描官网可能重新发现这些联系方式。

## 当前范围

- 无须联系人数据库订阅或搜索 API 密钥；不调用付费服务或 AI 接口。
- 扫描同一官网（包含 www 与非 www），优先联系、团队、管理层、招聘、采购和新闻页面，读取站点地图中的相关页面。
- 每次最多尝试24个页面，最多3个PDF；PDF最多读取前12页。扫描时间和单文件大小有限制，结果最多100项。
- 读取公开邮箱、电话链接、国际格式的正文电话和明确的 WhatsApp 链接；手机号与固定电话无法可靠区分时标为「类型待核实」。不推测号码对应WhatsApp。
- 仅在官网明确的 Person 结构化资料，或小型联系人卡片明确关联姓名时，自动记录归属。PDF资料和页面散落的联系方式默认保留为未具名结果，不把页面上的号码随意配给某人。
- 官网不公开的数据、需要登录的数据、浏览器动态加载但初始页面没有的数据，可能无法获得。当前版本不检索全网、不使用付费数据库、不猜测邮箱，也不进行邮箱投递或电话验证。
- 遵守网站公开访问规则；规则无法确认时停止扫描。不会访问本机、内网地址或跳转到其他域名。

## 去重与冲突

优先匹配相同邮箱，其次使用唯一的同名联系人，以及已存在的同一号码。公开电话和 WhatsApp 中的相同号码会合并展示。已有字段不会被不同的新值覆盖；发现冲突时整批不保存，并在相应结果旁说明。联系人在查找期间被其他窗口修改时，需要重新打开窗口读取最新资料。

同名不代表任职信息必然最新，历史招聘或新闻中的联系方式也可能失效。保存前仍需核对来源的日期和职位。

## 运维

新增依赖见 `requirements.txt`：beautifulsoup4、pypdf。应用启动时通过现有 SQLAlchemy 元数据机制创建 `crm_lead_contact_scans` 表，不迁移或改写既有联系人。

扫描任务使用应用进程内后台执行，同一进程最多并行3个任务。应用重启会中断正在扫描的任务；超过5分钟未更新的任务在窗口中显示为中断，可重新扫描。完成的结果及采集详情保留在扫描任务中，删除结果、删除线索或转换为客户时随原线索扫描记录清理；现有联系人资料与备注不会被删除。

接口位于 `/api/customer-workflow/projects/{project_id}/leads/{lead_id}/contact-scans`，沿用线索的项目、归属与写入权限。导入只接收服务器已保存结果的ID，不接受浏览器构造的任意联系人内容，并通过联系人版本校验避免覆盖并发修改。

验证：`tests/test_lead_contact_scan.py` 覆盖真实HTML/PDF提取、内网访问拦截、访问规则、归属、去重、冲突、持久化、权限、版本冲突及删除清理。`tests/lead_contact_scan_ui.cjs` 使用模拟业务接口验证桌面、手机端、勾选、冲突恢复、保存及来源转义，不修改真实业务资料。
